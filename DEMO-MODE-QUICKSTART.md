# RE-SKIN Demo Mode — Quick Start

Demo Mode lets you inspect both dashboards without connecting Supabase.

## Run locally

From this folder (the folder containing `package.json`):

```bash
npm install
npm run dev
```

If Supabase credentials are missing or still the example placeholders, Demo Mode turns on automatically in local development.

If you already have real Supabase credentials but want to preview the demo UI, add this to `.env.local`:

```env
RE_SKIN_DEMO_MODE=true
```

Then restart `npm run dev`.

## Open the dashboards

- Admin: <http://localhost:3000/admin>
- Member: <http://localhost:3000/dashboard>
- Landing page: <http://localhost:3000>

The dashboards include sample members, pickup requests, SKINPoint history, status filters, admin confirmation/cancellation, and simulated pickup verification.

All demo changes are held in temporary browser state. They do not write to Supabase and reset when the page is reloaded. The Admin and Member previews use separate sample data.

Demo Mode is disabled in production. A deployed Vercel site still requires Supabase Auth and the appropriate user role.

The simulated verification uses the point values already defined in this project's SQL schema: 5 points for 5–40 ml, 10 points for 50–100 ml, and 15 points for 200–500 ml. This is only a front-end preview; no point transaction is written to a database.

### Recommended demo walkthrough

1. Open `http://localhost:3000/dashboard` in one browser tab.
2. Open `http://localhost:3000/admin` in a second tab in the same browser.
3. In Member, choose **Ajukan pickup**. Admin should see the pickup appear and the notification bell count increase.
4. In Admin, confirm the pickup, then verify it. Member should receive status and SKINPoint notifications.
5. In Member, use the 1,000-point reward tier to submit a gift redemption request.
6. In Admin, approve or reject the redemption request. Member sees the result; rejected requests refund the reserved demo points.

The demo event stream is stored locally in the browser. It does not synchronize across different devices or browsers, and it is not a replacement for Supabase Realtime or production notifications.


## Procedure correction: pickup and reward handover

### Pickup request
- Clicking **Ajukan pickup** opens a form; it does not send a request or notify Admin yet.
- The member must provide date, time, pickup address, WhatsApp number, and estimated package quantities.
- The additional note is optional. An empty note stays empty and is not generated by the system.
- Only clicking **Kirim Pengajuan** creates the pickup record and notifies Admin. Admin sees only the details submitted by the member.
- Old V2 synthetic pickup events that contained the hard-coded note `Pengajuan pickup dari member area demo.` are removed during demo-event loading.

### Reward redemption and receipt
1. Member submits a reward redemption request. Points are reserved temporarily.
2. Admin approves or rejects. Approval means the reward is being prepared; it does not mean it has been handed over. Rejection returns the reserved points.
3. After approval, Admin selects direct pickup or delivery and enters the handover instructions (pickup location/schedule, or courier/tracking details).
4. The member sees the details in the redemption history and receives a notification.
5. After actually receiving the reward, the member clicks **Saya Sudah Menerima Hadiah**.
6. The redemption becomes **received/completed**, and Admin receives a notification that the member confirmed receipt.

All these flows are local demo simulations. Production must validate status transitions and persist them in Supabase; the actual item stock, delivery address, courier, and fulfillment evidence must be managed by the Admin.


## Update: Admin Profile and Account Deletion Requests

### Admin profile
- The top-right profile control displays a local illustrated profile image, admin name, role, email, account status, and join date.
- The dropdown includes a sign-out action. In Demo Mode, this only navigates back to the landing page; it does not invalidate a Supabase session because no authentication is connected.

### Member account deletion request
- The Member profile dropdown includes **Ajukan penghapusan akun**.
- Member must provide a reason (at least 10 characters) and type `HAPUS AKUN`.
- Submitting creates a local demo request; it does not delete any account or erase any data.
- The Admin dashboard displays a queue of account deletion requests and can approve or reject them.
- The member receives a notification when the request is submitted and when Admin reviews it.
- Admin approval only authorizes the request for final identity verification. Permanent deletion is not performed by this Demo Mode.
- When Supabase is connected, implement the `account_deletion_requests` table with RLS and a server-side review flow. Actual Auth user deletion must be handled only by a trusted server using the Supabase service role after final verification; never expose the service-role key in browser code.

## Update V8: WhatsApp Admin Notifications
Before testing the WhatsApp handoff, set `NEXT_PUBLIC_RE_SKIN_ADMIN_WHATSAPP` in `.env.local` to the Admin's real WhatsApp number in international format (for example, the format `628xxxxxxxxxx`, not a real sample number). Restart the development server. When a member submits a pickup or requests a reward, the app records the Demo event and opens WhatsApp with a prefilled message. The member must press **Kirim** in WhatsApp. The landing-page pickup flow follows the same pattern after Supabase confirms the pickup has been saved. Set the same variable in Vercel Environment Variables before deployment.
